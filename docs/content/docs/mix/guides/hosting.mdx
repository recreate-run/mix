Deploy Mix with local storage for self-hosted setups or Supabase for cloud deployments.

## Storage Backend Options

### Local (Only for testing)

**Configuration:**

```bash
# .env
STORAGE_TYPE=local
```

That's it! Local storage requires no additional configuration.

### Supabase Storage (Cloud)

Best for production deployments with multiple instances or when you need cloud-hosted files.

**Automated Setup (Recommended):**

```bash
./scripts/setup-supabase.sh
```

This script will:
1. Install Supabase CLI if needed
2. Authenticate with your Supabase account (browser-based)
3. Let you select or create a project
4. Automatically fetch API keys
5. Create storage bucket
6. Update your `.env` file

Everything configured in one command!

## How Storage Works

Mix uses a **StorageProvider abstraction** that makes storage backend transparent:

- **File uploads** are automatically stored using the configured provider
- **Thumbnails** are generated and stored in the same provider
- **File serving** adapts based on storage type:
  - **Local**: Files served directly via HTTP
  - **Supabase**: Redirects to Supabase public URLs

All file operations (upload, download, list, delete) work identically regardless of storage backend.

## Environment Variables

### Required for All Deployments

#### Database (Turso)

**Automated Setup (Recommended):**

```bash
./scripts/setup-turso.sh
```

This script will:
1. Install Turso CLI if needed
2. Authenticate with your Turso account (browser-based)
3. Let you select or create a database
4. Automatically fetch database URL and auth token
5. Update your `.env` file

Everything configured in one command! For manual setup or more details, see [Database Configuration](/docs/mix/database).

**Manual Configuration (Alternative):**

```bash
# Database (Turso)
MIX_DB_TYPE=turso
MIX_DB_TURSO_URL=your_turso_database_url
MIX_DB_TURSO_AUTH_TOKEN=your_turso_auth_token

# Frontend URLs (adjust for your deployment)
VITE_BACKEND_URL=https://your-backend-url.com
VITE_GSAP_URL=https://your-gsap-url.com
```

### Storage Configuration

```bash
# Local storage (default)
STORAGE_TYPE=local

# OR Supabase storage
STORAGE_TYPE=supabase
STORAGE_ENDPOINT=https://project.supabase.co
STORAGE_BUCKET=bucket-name
STORAGE_ACCESS_KEY=service_role_key
```

## Production Best Practices

1. **Use Supabase for production** deployments with multiple instances
2. **Use local storage** for self-hosted single-instance deployments
3. **Always use service_role key** for Supabase (never commit to git!)
4. **Set bucket to public** for file access
5. **Monitor storage usage** in Supabase dashboard
6. **Enable backups** for local storage deployments
7. **Use environment variables** for all secrets (never hardcode)

## Troubleshooting

### Files not appearing in Supabase

**Check:**
1. Is `STORAGE_TYPE=supabase` set?
2. Are you using the `service_role` key (not anon key)?
3. Is the bucket public?
4. Check backend logs for upload errors

### Thumbnails not working

**Check:**
1. Is FFmpeg installed on the server? (required for video thumbnails)
2. Check backend logs for thumbnail generation errors
3. Verify storage provider has write access

### 404 errors on existing files

**Cause:** Files were uploaded to local storage, but you switched to Supabase (or vice versa)

**Solution:** Migrate files to new storage provider (see Migration section above)
