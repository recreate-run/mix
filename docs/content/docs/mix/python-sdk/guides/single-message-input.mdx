title: "Single Message Input"
description: "One-shot queries with session state and resuming"
---

Single message input mode provides a **simpler API** for one-shot queries while still maintaining session state and context. It's ideal for stateless applications or when you don't need real-time streaming updates.

## Overview

Single message mode:
- Sends a message and waits for the complete response
- Uses existing session state (if session exists)
- Returns the final result without streaming events
- Simpler to implement than streaming mode
- Still supports tool execution and file operations

## When to Use Single Message Input

Use single message input when:

✅ **Simple queries** - One-off questions without complex workflows
✅ **Stateless APIs** - REST endpoints that return complete responses
✅ **Background tasks** - Batch processing without user interaction
✅ **Testing/Scripts** - Quick scripts that don't need streaming
✅ **Legacy integration** - Systems that expect synchronous responses

## When NOT to Use

Avoid single message mode for:

❌ **Long-running tasks** - No progress visibility during execution
❌ **Interactive UIs** - Users see nothing until completion
❌ **Multi-step workflows** - Can't show intermediate tool calls
❌ **Permission requests** - Can't handle interactive approvals

## Implementation Example

### Basic Single Message

```python
from mix_python_sdk import Mix
import os

def ask_question(question: str) -> str:
    """Send a single message and get complete response"""

    with Mix(server_url=os.getenv("MIX_SERVER_URL")) as mix:
        # Create or reuse session
        session = mix.sessions.create(title="Q&A")

        # Send message and wait for response
        response = mix.messages.send_message(
            id=session.id,
            request_body={
                "text": question
            }
        )

        # Extract response text
        return response.content

# Usage
answer = ask_question("What is the capital of France?")
print(f"Answer: {answer}")
```

### With Session Persistence

```python
from mix_python_sdk import Mix
import os

class ChatBot:
    def __init__(self):
        self.mix = Mix(server_url=os.getenv("MIX_SERVER_URL"))
        self.session = None

    def start_conversation(self):
        """Initialize a persistent session"""
        self.session = self.mix.sessions.create(title="ChatBot Session")
        print(f"Session started: {self.session.id}")

    def ask(self, message: str) -> str:
        """Send message using existing session context"""
        if not self.session:
            raise ValueError("No active session. Call start_conversation() first")

        response = self.mix.messages.send_message(
            id=self.session.id,
            request_body={"text": message}
        )
        return response.content

    def end_conversation(self):
        """Clean up session"""
        if self.session:
            self.mix.sessions.delete(id=self.session.id)
            self.session = None
        self.mix.close()

# Usage with context
bot = ChatBot()
bot.start_conversation()

print(bot.ask("What's the weather in Paris?"))
print(bot.ask("What about London?"))  # Uses previous context
print(bot.ask("Compare them"))        # Remembers both cities

bot.end_conversation()
```

### Stateless API Pattern

```python
from mix_python_sdk import Mix
from fastapi import FastAPI, HTTPException
import os

app = FastAPI()
mix = Mix(server_url=os.getenv("MIX_SERVER_URL"))

@app.post("/ask")
async def ask_ai(question: str, session_id: str = None):
    """Stateless endpoint with optional session resumption"""

    try:
        # Reuse or create session
        if session_id:
            # Resume existing session
            sessions = mix.sessions.list_sessions()
            if not any(s.id == session_id for s in sessions):
                raise HTTPException(status_code=404, detail="Session not found")
        else:
            # Create new session
            session = mix.sessions.create(title="API Query")
            session_id = session.id

        # Send message
        response = mix.messages.send_message(
            id=session_id,
            request_body={"text": question}
        )

        return {
            "answer": response.content,
            "session_id": session_id
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))

@app.on_event("shutdown")
async def shutdown():
    mix.close()
```

### Batch Processing

```python
from mix_python_sdk import Mix
import os
import csv

def analyze_feedback_batch(csv_file: str):
    """Process multiple items without streaming"""

    with Mix(server_url=os.getenv("MIX_SERVER_URL")) as mix:
        # One session for all items
        session = mix.sessions.create(title="Batch Analysis")

        results = []

        with open(csv_file, 'r') as f:
            reader = csv.DictReader(f)
            for row in reader:
                feedback = row['feedback']

                # Analyze sentiment
                response = mix.messages.send_message(
                    id=session.id,
                    request_body={
                        "text": f"Analyze sentiment (positive/negative/neutral): {feedback}"
                    }
                )

                results.append({
                    "feedback": feedback,
                    "sentiment": response.content,
                    "id": row['id']
                })

        # Cleanup
        mix.sessions.delete(id=session.id)

        return results

# Process 100 items in batch
results = analyze_feedback_batch("customer_feedback.csv")
print(f"Processed {len(results)} items")
```

## Response Format

The `send_message` response includes:

```python
{
    "content": str,        # The AI's response text
    "session_id": str,     # Session used
    "message_id": str,     # Unique message identifier
    "timestamp": str,      # When response was generated
}
```

## Best Practices

### 1. Reuse Sessions for Context

```python
# ✅ Good - Maintains conversation context
session = mix.sessions.create(title="Analysis")
result1 = mix.messages.send_message(id=session.id, request_body={"text": "Load data.csv"})
result2 = mix.messages.send_message(id=session.id, request_body={"text": "Analyze column A"})
result3 = mix.messages.send_message(id=session.id, request_body={"text": "Plot results"})

# ❌ Bad - No context between messages
for msg in ["Load data.csv", "Analyze column A", "Plot results"]:
    session = mix.sessions.create(title="Task")
    mix.messages.send_message(id=session.id, request_body={"text": msg})
```

### 2. Handle Timeouts

```python
# ✅ Good - Set reasonable timeout
from mix_python_sdk import Mix
import httpx

mix = Mix(
    server_url=os.getenv("MIX_SERVER_URL"),
    client=httpx.Client(timeout=60.0)  # 60 second timeout
)

try:
    response = mix.messages.send_message(
        id=session_id,
        request_body={"text": "Complex analysis task"}
    )
except httpx.TimeoutException:
    print("Request timed out. Consider using streaming mode.")
```

### 3. Clean Up Resources

```python
# ✅ Good - Always cleanup
session_id = None
try:
    session = mix.sessions.create(title="Task")
    session_id = session.id
    result = mix.messages.send_message(
        id=session_id,
        request_body={"text": "Do something"}
    )
finally:
    if session_id:
        mix.sessions.delete(id=session_id)

# ❌ Bad - Leaks sessions
session = mix.sessions.create(title="Task")
result = mix.messages.send_message(id=session.id, request_body={"text": "Do something"})
# No cleanup
```

## Limitations

⚠️ **No Real-time Feedback**: Can't see progress during long operations
⚠️ **Timeout Risk**: Long-running tasks may exceed HTTP timeout
⚠️ **No Tool Visibility**: Can't show intermediate tool executions
⚠️ **Memory Intensive**: Full response loaded in memory
⚠️ **No Interruption**: Can't cancel once sent

## Comparison: Streaming vs Single Message

| Feature | Streaming Input | Single Message |
|---------|----------------|----------------|
| Real-time updates | ✅ Yes | ❌ No |
| Progress visibility | ✅ Yes | ❌ No |
| Tool execution feedback | ✅ Yes | ❌ No |
| Simple implementation | ❌ More complex | ✅ Simpler |
| Stateless APIs | ❌ Not ideal | ✅ Perfect |
| Long-running tasks | ✅ Recommended | ❌ May timeout |
| Session context | ✅ Yes | ✅ Yes |
| File operations | ✅ Yes | ✅ Yes |

## When to Switch to Streaming

Consider switching to streaming mode if you experience:

- Frequent timeouts on complex queries
- Users asking "is it still working?"
- Need to show tool execution progress
- Want to handle interruptions gracefully
- Building interactive chat interfaces
